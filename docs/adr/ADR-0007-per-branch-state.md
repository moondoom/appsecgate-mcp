# ADR-0007: Per-branch state

**Статус:** Proposed
**Дата:** 2026-10-31
**Файл:** `docs/adr/ADR-0007-per-branch-state.md`
**Блокирует:** не блокирует Фазу 2; блокирует classic.
**Контекст:** заглушка — решения фиксируются после Фазы 2 (SM-1..SM-6).
**Связанные:** ADR-0001 (fingerprint), ADR-0005 (state machine), ADR-0006 (lifecycle model)

---

## 1. Контекст

Classic multi-version: ключ `(project, fp)` один на все ветки — недостаточно,
когда фикс подтверждён (`FIXED`) или отклонён (`WONT_FIX`) на одной ветке,
а на другой находка ещё актуальна. Состояние должно жить per-branch.

## 2. Модель

PK находки расширяется до `(project, branch, fp)`; координаты `branch`/`commit`
(ADR-0006 §1.2) становятся частью идентичности, а не метаданных.

## 3. Распространение состояния

Перенос `WONT_FIX`/`SUPPRESSED`/`FIXED` между ветками — через merge/cherry-pick
(источник: git-граф); правила наследования и конфликтные случаи — TBD.

## 4. Snapshot

Влияние на event-log (`schema_version`, ADR-0006 §3.3): события получают `branch` —
формат и миграция строк — TBD.

## 5. Миграция

Пересоздание `shown_findings` с новым PK (no-migration, ADR-0005 §2.7);
пересчёт агрегатов — TBD.

## 6. Влияние на ADR-0006

Пересматриваются: §1.2 (координаты), §2.3 (гейт-матрица, `wont_fix_other_branch`),
§3.4 (cross-source consistency), §1.7 (новые конфиг-ключи).
